# lean-ops

一个给 AI Agent 用的技能包：**用最少的 token 把活干完**。

不是让你少思考，是让你少读。上下文被两样东西吃掉：灌满屏的工具输出，和把同一件事说两遍。

## 内容

单文件技能 `SKILL.md`，六节 22 条：

- **工具调用**：合并调用、裁输出、先看结构再读内容、探针先行
- **委派**：能派出去的别自己烧、任务一次说清、不发回执
- **产出**：长内容落文件、聊天只给三行、不复述
- **执行节奏**：验收标准先写死、调研只做一次、失败三次就停
- **上下文降级**：大资产用脚本查不读入、参考只读 1-3 份、分段续跑
- **自检**：删掉一半，信息还完整吗

末尾附「反例表」——每条都是实际踩过、写明代价的，不是凭空建议。

## 安装

把它放进你的 skills 目录，让宿主按 `description` 自动触发，或在任务开始前显式加载：

```
<your-skills-dir>/lean-ops/SKILL.md
```

Claude Code / Codex / DSH 一类的宿主都能直接读这种 `SKILL.md` 结构（YAML frontmatter + Markdown 正文）。

## 什么时候用

- 要翻大量文件、日志、目录树
- 多 Bot / 子代理协作，需要控制交接成本
- 上下文开始吃紧，开始重复读同一份东西
- 写交付物，纠结该写多长

## 什么时候不该用

- 一次性小脚本（< 50 行无依赖），直接写
- 安全审计、合同审阅、逐行评审——这些以完整为准，省流让位于正确
- 对方明确要详细过程时
